# AC-P3：Windows 路径兼容性——候选目录与工件目录相互包含判断

状态：已登记，待最小修复
负责人：A 协调；实现交 C+D 或指定工程 Agent（改动面：src/core/candidate.ts 目录所有权检查）
关联：与 B-ENV-1、AC-P2a/AC-P2b 分开登记、分开排期；属 Windows 路径兼容性，
不改变 SourceGraph / Scope / Candidate 的安全证明规则。

## 1. 问题

`candidate.ts` 中候选目录与工件目录的相互包含判断缺少 `path.isAbsolute` 检查：
相对路径片段经 `path.relative` 计算后，Windows 不同盘符目录可能产生
不可预期结果（如 `C:` 与 `D:` 目录间 relative 返回带盘符的绝对路径），
导致**跨盘完全不相干的目录被误拒绝**。

## 2. 最小修复方向

- 目录所有权检查前先对两侧路径做 `path.resolve` 归一化 +
  `path.isAbsolute` 校验；盘符（drive）不同的路径对直接判定为
  "不相交"，进入允许分支。
- 归一化须覆盖：`..`/`.` 段、尾部分隔符、大小写差异（Windows 不敏感）、
  8.3 短名边界；UNC 路径（`\\server\share`）与带盘符路径的交集判断
  保守处理。
- 符号链接：现有保护语义不变——对符号链接边界继续保守
  （无法证明目标归属时拒绝，不得因本修复出现绕过路径）。

## 3. 正反例（必须全部进测试）

| 场景 | 期望 |
|---|---|
| 同盘目录互相包含（候选目录在工件目录内，或反之） | **拒绝**（维持现状） |
| 同盘完全不相干目录 | 允许 |
| 跨盘（C: vs D:）完全不相干目录 | **允许**（本修复目标） |
| 跨盘但存在包含语义的表达（如 subst 挂载） | 拒绝（保守） |
| UNC 路径与本地盘符路径 | 视为不相交，保守判定 |
| 经符号链接指向对方目录 | 拒绝（所有权保护不可绕过） |

## 4. 明确禁止

- 不得以本修复放宽同盘包含拒绝语义。
- 不得绕过候选 worktree 标记校验与工件目录归属检查。
- 不改变 SourceGraph / Scope / Candidate 的安全证明规则。
