## 一、作品概述

**尚未落笔，先见涟漪。**

涟漪（Ripple）是一个让不懂代码的人也能在获得授权的网站上安心改内容的工具。想改网页上的一句话、一张图或一个品牌色时，涟漪先告诉你：这次改动会影响哪些页面、在手机上会发生什么变化；你确认范围之后，它把修改放进一个隔离的副本里真实运行一遍，给出看得见的证据；确认无误再应用，随时可以回滚。

这里的「应用」发生在网站的一份隔离副本上，原网站代码全程只读保护；涟漪当前提供的是修改的预演、验证与回滚，不包含面向生产环境的发布托管服务。

首期面向获得授权的 React/Vite 工程。主项目开源公开：<https://github.com/Onesummer-D/Ripple>；验收记录与证据链接公开可查（真实工程为私有仓，CI 工件有保存期限，长期副本已归档于仓库 `docs/delivery/evidence/run18/`）。

## 二、项目背景

企业网站、活动页、电商专题大多由建站公司交付，日常维护却落在不懂技术的运营同学身上。「改一句文案」这类小事，背后是共享组件、共享数据源和响应式布局——改一处、动三页，手机上按钮被挤出去，接过网站运营的很多同学都遇到过。

不少 AI 编程工具已经能直接帮忙改代码，但接手网站的人真正卡住的往往是两个更要紧的问题：**这次改动会影响哪里？后果是什么？** 涟漪把这两个问题变成可以看见、可以验证、可以反悔的流程。

## 三、用户需求

- **接手网站的运营人员**：只想改首页那一句活动文案，不希望波及既有的活动落地页和商品专题页。
- **建站服务商**：把网站交给客户自助维护，需要每次修改自带影响说明、验证证据和回滚保障。

用户要的不是又一个对话框，而是一次「先看见后果、再做决定」的确定感。

## 四、核心功能（三层分清：已验证 / 演示体验 / 正在集成）

**第一层 · 已验证的核心能力**——在真实青野文创工程（获得授权、版本固定）上于一次自动验收中完整走通（Run #18，2026-10-22）。以下每一步都有真实浏览器证据留档：

1. **网页上点选，直接定位源码**：在网页里点一下要改的文字，涟漪指出它来自哪个源文件、哪一行，并标明这个元素的身份可信度。
2. **先预览，再决定**：输入新文案生成修改候选后，涟漪在隔离环境里用桌面、平板、两台手机的四种屏幕尺寸真实渲染，检查目标是否按预期变化、范围内的页面是否同步、范围外的页面是否原样保持。
3. **每条结论都有证据**：验证结果可以逐条打开，是带数字指纹（哈希）绑定的截图与运行记录，可下载、可复核。
4. **你确认后才应用**：只有完整跑完且身份一致的验证记录才允许进入应用；改单个位置还是同步关联位置由你决定，拿不准来源的页面会被安全门拦下。
5. **应用、逐页检查与回滚**：应用的正是验证过的那一份修改；应用后可以逐页检查；不满意一键回滚，原网站代码保持原样。
6. **历史记录可恢复**：版本历史里可以回看，选中的历史候选能够恢复，连同它的验证状态一起还原。

> 边界说明：以上能力运行在授权工程的一份隔离副本上，解决的是「安全地改、验证过再改、改错能反悔」；它不包含把修改直接发布到生产环境的服务。

**第二层 · 已有的演示体验**——F 体验工作台已具备真实可操作的交互界面（画布、关系涟漪图、范围决策、前后对照、版本胶片），录屏画面均带 DEMO 标注。关系图与范围决策的底层能力已在第一层真实验收中作为验证输入使用；F 的真实 TEXT 候选接入与四视口展示已完成（feat/f-real-text-phase2-20261023，2026-10-23 协调方口径），正在并入公共核心，演示界面与真实验收证据的来源标注仍须分开。

**第三层 · 正在集成——方向明确、边界如实**

- 体验工作台与真实验收链路的统一接入（Real Adapter）正在并入公共核心（F 真实 TEXT 候选与四视口展示已完成）；E 视觉证据阶段一只读接线已并入（PR #30），MEDIA 流程的真实样本采集同理待接入后完成。
- 图片素材替换的视觉差异证据（像素级对比与布局规则分析）已在模块层就绪并接入验证流水线（只读挂载，不改变审批门控）；素材替换本身已在真实网站完成过一次完整验收（替换分类图，含四屏验证与应用回滚）。严格实例证明（阶段二）待 C+D 合同冻结。
- 品牌色（CSS Token）修改与第三方开源网站的完整适配在路线图中：面对陌生开源项目，涟漪会如实报告「哪些关系已证实、哪些尚不可判定」，不猜、不装。

## 五、创新设计

1. **把「影响」变成一等公民**：传统编辑从修改开始，涟漪从影响的可见化开始——结构涟漪（谁和我共享）、渲染涟漪（四块屏幕上的真实变化）、证据解读（把技术结论翻译成人话），三层叠加成一次连贯的决策体验。
2. **变化不等于问题，没问题不等于通过**：涟漪的视觉证据有自己的语言——检测到变化不直接判风险，没检测到变化也不直接判通过；意图是否达成，以真实运行的结构化断言为准。这套「从不把未知说成通过」的纪律贯穿整个工具。
3. **一份修改，全程同一份**：验证、应用、回滚使用的始终是同一个修改包，中途不会重新生成；回滚会保护你在应用之后又做的新改动。
4. **失败也是作品的一部分**：真实网站验收经历多轮失败，每一轮都被完整归因（资源加载、并发限制、导航行为、预览挂载），修复全部带有防再犯的测试；最终完整流程一次通过并全程留证。

## 六、技术实现（评委速览版）

- 静态分析读懂真实工程结构，运行时标注区分「看起来共用」与「真的共享同一数据源」。
- 修改候选在与原网站隔离的环境中构建，带内容指纹，防止被替换或篡改。
- 外部图片、字体等资源必须经用户明确授权才联网，且先留快照留证。
- 验证在隔离容器里以四种真实屏幕尺寸运行浏览器，输出带哈希绑定的截图与结构化记录；外部资源一律默认拦截。
- 审批安全门只承认「完整跑完且身份一致」的验证记录；没跑完、跑失败的记录不会被当成通过。
- 应用与回滚直接作用于同一份带指纹的修改包，原网站全程只读保护。

（研发口径的完整架构说明见仓库 DEV_HANDOFF 与 docs/architecture。）

## 七、应用价值

- **运营同学**：日常改文案、换图、调色不再提心吊胆，每次修改有证据、可回滚。
- **建站服务商**：把「影响说明 + 验证证据 + 回滚保障」变成交付物，客户自助维护也安全。
- **方法与边界**：「先见涟漪再落笔」的交互范式可迁移到任何「共享来源、多处呈现」的数字内容（设计系统、多渠道文案、素材库）；同时示范了 AI 辅助工具应有的诚实——未知就是未知。

## 八、真实性与出处

以下事实均可在公开仓库核对（2026-10-23）。主项目开源；真实验收所用青野工程为私有仓，验收记录链接公开、CI 工件有保存期限，完整证据已归档于仓库 `docs/delivery/evidence/run18/`（含哈希索引）：

- **主案例真实验收已通过**：在真实青野文创网站（React/Vite，四个页面，固定版本）上，从「导入工程 → 点选 footer 文字 → 生成候选 → 四屏验证（七项检查全部通过）→ 范围决策 → 审批 → 应用 → 应用后逐页检查 → 回滚 → 历史恢复」全流程一次跑通（浏览器验收用例耗时 1.4 分钟，整轮工作流约 2.7 分钟）；执行记录与四屏截图带哈希绑定，随验收工件公开并已在仓库归档（Run #18，<https://github.com/Onesummer-D/Ripple/actions/runs/39808500782>）。
- **图片替换**：在真实网站上完成分类图替换全流程验收（四屏验证、应用与回滚、原网站未改动证明，2026-10-21）。
- **第三方开源站**：对 MIT 许可的开源项目做过能力盘点——媒体引用关系可证实，但动态路由与样式变量尚不可判定，如实列为「未知/不支持」，对应完整流程未运行。
- **演示画面纪律**：录屏中的演示数据一律带 DEMO 标识；概念设计稿一律标注「概念效果示意」，不冒充实测截图。
